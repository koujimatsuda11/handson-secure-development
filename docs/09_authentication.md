# 認証のセキュリティ要件
この章は、認証を強化します。

- 適切なパスワード強度
- 安全なパスワード回復の仕組み
- 安全な方法でパスワードを保存する
- その他パスワードに関する要件
- 一般的な認証の要件

## 適切なパスワード強度

パスワード強度に関する要件を確認します。このアプリケーションでは、 Magnito(Cognitoエミュレータ)を使っています。実際には、Cognitoを使うことになると思います。パスワードの強度などは、Cognitoで設定します。

- パスワードの最低文字数は 8 文字であるが、最低限 15 文字にすることを強く推奨する
- 64 文字以上の長さが許可されている。ただし、Dos対策のため、最大文字数は必ず設定
- 切り捨てや大文字小文字の変換などの修正を加えない。
- 使用可能な文字の種類を制限するパスワード規則がない。大文字、小文字、数字、特殊文字の要求を設けてはいけない。
- Pwned Passwordsなどのサービスを利用して、侵害されたパスワードをブロック
- システム固有の単語をリスト化し、推測されやすいパスワードが作成されることを防ぐ

``` typescript
passwordPolicy: {
  minLength: 8, // 最低文字数
  requireLowercase: false, // 小文字は任意
  requireUppercase: false, // 大文字は任意
  requireDigits: false, // 数字は任意
  requireSymbols: false, // 記号の使用は任意
},
```

## その他パスワードに関する要件
基本的には、ほとんどCognitoのデフォルトの設定で問題ありませんが、「パスワードが変更または置き換えられた場合、ユーザにこのイベントが通知される。」は、現時点では実装が難しいです。今後のCognitoのアップデートに期待しましょう。

## 一般的な認証の要件
パスワード以外の一般的な認証に関する要件を確認します。

### 自動化された攻撃から保護する
Cognitoは、勝手にアカウントロックを行います。外すことができませんし、カスタマイズもできません。

https://docs.aws.amazon.com/ja_jp/cognito/latest/developerguide/authentication.html

### 全ての認証処理をログに残す（成功、失敗を含む全て）
Cognitoでは、アクティビティの記録は、Plusプランからです。Essentialsプランは、10,000MAUの無料枠がありますが、Plusプランには、無料枠がありません。Essentialsプランを開発用と考えるなら、Plusプランは本番環境用のプランと考えいいと思います。さらに、脅威保護を監査モードでONにすることで、アクティビティログを記録します。

また、Plusプランにすることにより、以下も満たすことができます。

- 悪意のあるサインイン試行からの保護 / リスクベースのアダプティブ認証 → 不明な場所や危険な場所からのログインをブロックしたり、通知したりする
- 安全でないパスワードから保護するための、侵害された認証情報の検出 → 侵害されたパスワードをブロックを行うことができます。

本番環境では、Plusプランで利用しましょう。

### 弱い認証 (SMS や電子メールなど) が、よりセキュアな認証の代わりとしてではなく、二次検証とトランザクション承認に限定されている
アプリケーションの実証次第です。弱い認証のみにすることもできますので、注意しましょう。
